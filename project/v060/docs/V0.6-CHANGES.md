# v0.6.0 — Contextual Mic Bubble: what changed

Base: Drive source `VoiceDock-AI-v0.5.0-source.zip` (235 files, versionCode 5 / 0.5.0).
Working copy: `voicedock-v0.6/` (this folder). Pristine audit reference: `../review/`.

## User-visible

1. **Default UI is only a 54dp floating mic bubble.** Tapping it now *does* something:
   `SCANNING` → one on-tap screen probe → a compact context card or the assistant's own chat bubble.
2. **The assistant types its own greeting** ("মেসেজ বক্স পেয়েছি…" / "How can I help?") with a
   typewriter effect. No cloud call, no invented number.
3. **Two window modes.** Context card = `FLAG_NOT_FOCUSABLE` (the app underneath keeps the cursor).
   Assistant chat = focusable `FLAG_NOT_TOUCH_MODAL` (you can actually type — v0.5's panel could not).
4. **Outside-tap dim / blur**, draggable bubble, close ✕, settings ⚙, local/remote badge.
5. **Privacy guard.** Known finance apps and VoiceDock itself are blocked before traversal; password
   text is skipped and recognizable PIN/OTP/card strings trigger redaction. These rules are heuristic:
   the local probe cannot reliably detect every protected/FLAG_SECURE screen. Disable screen-context
   consent in sensitive apps. Remote Explain separately fails closed when window capture fails.
6. **Explicit approval.** "Insert here" is a separate tap on a visible draft. Nothing is typed into
   another app automatically.
7. **No microphone needed** just to open the bubble, read context or type a question.
8. **3-tab navigation** (Home / Dictate / Settings) instead of 5; Knowledge and Drafts reachable
   from Home cards and Settings links.
9. **Just-in-time consent dialog** on first bubble start; 8 granular switches in
   Settings → ভাসমান সহকারী (v0.6).
10. **Offline intent router** understands common Bangla/English commands (কী ঘটেছে, সারাংশ,
    আজকের কাজ, মনে রাখো, copy, explain, …) and answers honestly that it is rule-based.

## Architecture (the 4 non-negotiable decisions)

| Decision | How v0.6 implements it |
|---|---|
| Memory ≠ Model | `context/` is a pure, Android-free, unit-tested rules layer. `LocalIntentRouter` can be swapped for a 2M model without touching UI/memory. No memory tables yet (v0.7). |
| Device access ≠ AI layer | `device/ScreenProbe.kt` + `device/AgentSafetyOracle.kt` are the ONLY Android adapters. `SafetyOracle` is the seam; production delegates to v0.5 `AgentSafety`. |
| Background collection ≠ activation | `VoiceDockNotificationListener` is a declared **no-op**. Activation = `AssistantOverlayService` + one `ScreenProbe` on tap. |
| Local-first = integrated | Local DB (v0.2 drafts/knowledge), local rules, local Whisper STT, local Keystore secrets. Remote AI optional, default-off, consent-gated. |

## Real bug fixes found in the audit

- `AiPolicy.blockReason()` — `localOnly` blocked the user's own Ollama/LM Studio server. Fixed:
  `isLocalEndpoint()` recognises loopback + RFC1918; public `http://` now returns `insecure_url`.
- `res/xml/network_security_config.xml` — cleartext was forbidden while `AppSettings.customAiUrl`
  documented `http://192.168.0.10:11434/v1`. Fixed with a narrow exact-host allow-list
  (Android cannot express CIDR; see `LOCAL-AI.md`).
- `OverlayService.setStripTouchable()` — replaced all window flags instead of flipping one bit.
  Fixed with bitwise `and`/`or`.
- `OverlayPanel.FutureChips()` — dead code, removed.
- `PRIVACY.md` claimed "Overlay … never reads other apps" — rewritten for the on-tap probe.
